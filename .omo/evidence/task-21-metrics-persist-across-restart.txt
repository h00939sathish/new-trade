DESIGN DECISIONS:
  - Schema is narrow (one table, not one table per metric):
    adding new metrics (Task 22: PnL, exposure, etc.) requires
    no schema migration. Matches Prometheus data model.
  - 1-minute buckets: fine-grained enough for 5-minute-candle
    paper-trading; coarse enough to keep table small
    (~43k rows/month).
  - Persistence is OPT-IN via store= constructor param: tests
    that don't need persistence (8/9 tests in test_metrics.py)
    get in-memory-only behavior, zero filesystem touches.
  - Counters remain the source of truth for prometheus_text():
    the write buffer is drained by an async task every 10s, so
    the hot path is still O(1) per count.
  - attach_store() is the runtime hook (not setattr): clear
    API, can do bookkeeping, leaves the existing flush task
    running (it picks up the new store on its next tick).
  - Counter values accumulated BEFORE attach_store() are NOT
    backfilled: documented in test_collector_attach_store_at_runtime
    and the method's docstring.
