DESIGN DECISIONS:
  - Gauges are NOT restored on startup (load_from_store skips
    them): a portfolio agent re-emits them on the next
    portfolio update, and a stale last-write-wins value
    would be misleading. Counters ARE restored. This is
    documented in the MetricsCollector class-level comment
    and in the gauge-vs-counter schema note.
  - Daily PnL reset is automatic via date.today() check on
    every update_portfolio_state() call — no cron, no
    separate task. The reset is cheap (one date() call) and
    the baseline is updated in O(1).
  - 1-Hz throttle matches the plan's "1-second cache" rule
    and is well within Prometheus scrape resolution (15-30s
    typical). Without throttle, a fast fill stream would
    produce 5+ writes per fill, defeating the purpose of
    the persistence layer.
  - The 5 gauges are flushed in a single batched transaction
    (same as the counter increments), keeping the WAL
    commit rate low.
  - _count_open_positions() extracted as a helper so the
    metrics hook and health() share one source of truth
    (previously the logic was inlined in health()).
